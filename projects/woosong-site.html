Overview

우송대학교 RISE U-늘봄 사업단은 늘봄 강사를 양성하는 과정을 운영합니다. 과정 안내와 공지, 수강 신청, 신청자 관리를 한곳에서 할 사이트가 필요했습니다. 다른 대학의 늘봄 사이트를 디자인 참고로 삼되, 메뉴와 화면은 우송대 사업단에 맞게 새로 구성했습니다.

화면을 빨리 보여 드리려고 Next.js로 프로토타입을 먼저 만들고, 학교 쪽 개발자가 받아 쓸 수 있도록 같은 화면을 HTML 퍼블리싱 파일로 다시 정리했습니다. 마지막으로 실제 신청과 관리가 동작하는 Express 서버를 붙였습니다.

What I Did

  • 기능명세서: 화면, 데이터, 입력값 검사, 권한, 반응형, 만들지 않은 기능과 그 이유
  • 교육생과 관리자 화면 퍼블리싱
  • 서버: 로그인과 세션, 게시판 4종(공지사항, 자료실, 보도자료, 질의응답)의 검색과 페이지 나누기, 과정과 신청자 관리, 파일 첨부, 엑셀 내려받기 (Express, better-sqlite3, express-session, multer, bcryptjs, exceljs)
  • 점검: 서버 기능 점검표, 화면 크기별 가로 스크롤, 상태별 테스트 계정(관리자, 승인, 승인 대기, 정지)

Problem Solving

모집 상태가 신청 기간과 어긋날 수 있는 구조

문제
받은 자료에는 과정마다 '접수중' 같은 상태 값이 따로 붙어 있었습니다. 그대로 저장하면 신청 기간이 지나도 누군가 바꾸기 전까지 '접수중'으로 남을 수 있었습니다.
해결
상태를 입력 항목에서 빼고, 조회할 때마다 신청 시작일과 종료일을 오늘 날짜와 비교해 접수예정, 접수중, 모집종료로 계산했습니다. 수강 신청은 서버가 다시 검사해 접수중이 아니거나 정원이 찼거나 승인 전·정지 계정이면 거부합니다.
결과
관리자가 상태를 손으로 바꿀 일이 없어졌고, 화면 표시와 신청 가능 여부가 같은 기준을 따릅니다.

한글 첨부파일 이름이 깨짐

문제
한글 이름의 파일을 올리면 저장된 이름이 깨졌습니다. 업로드 라이브러리(multer)가 파일 이름을 latin1로 읽고 있었습니다.
해결
받은 이름을 UTF-8로 다시 해석해 저장했습니다.
결과
한글 파일을 올리고 내려받는 왕복 점검을 통과했습니다.

모바일에서 가로 스크롤이 생김

문제
좁은 화면에서 페이지가 옆으로 밀렸습니다. CSS Grid 자식의 기본 최소 너비(min-width: auto) 때문에 긴 표가 칸을 넓히고 있었습니다.
해결
칸에 min-width: 0을 주고, 표는 따로 가로로 넘겨 보는 영역으로 감쌌습니다.
결과
PC, 태블릿, 휴대폰 크기에서 모두 가로 스크롤이 없습니다.

컬럼을 추가하면 쌓아 둔 데이터가 지워질 상황

문제
질의응답을 회원 전용으로 바꾸면서 글에 작성 회원 컬럼이 필요해졌는데, DB를 새로 만들면 테스트하던 데이터가 사라졌습니다.
해결
서버가 켜질 때 컬럼이 없으면 그 컬럼만 추가하는 함수를 만들고, 기존 글에는 작성 회원을 연결했습니다.
결과
데이터를 지우지 않고 구조를 바꿨습니다.

Decisions

  • 표를 JavaScript로 그리던 코드를 일반 HTML로 되돌렸습니다. 나중에 이 화면을 JSP로 옮길 사람이 구조를 바로 볼 수 있어야 했기 때문입니다.
  • 질의응답을 로그인한 사람만 쓰게 바꿔, 작성자 이름과 이메일 같은 개인정보 입력란 자체를 없앴습니다.
  • 교육생은 학교 계정이 없는 외부인이라 학교 통합 로그인 대신, 수강 신청 때 계정을 만들고 관리자가 승인하는 방식으로 했습니다.
  • 서버가 퍼블리싱 파일의 CSS와 이미지를 복사하지 않고 그대로 쓰게 해, 디자인을 고치면 두 곳에 동시에 반영되게 했습니다.

Security

  • 적용한 것: 비밀번호 bcrypt 해시 저장, 교육생과 관리자 세션 분리, 승인 대기와 정지 계정 로그인 차단, 관리자 화면 세션 확인과 활동 기록, 비공개 문의는 작성자와 관리자만 열람
  • 공개 배포 전에 할 것(README에 적어 둠): 세션 키를 환경변수로 분리, HTTPS와 secure 쿠키, CSRF 토큰, 관리자 영역 접근 제한, 업로드 파일 확장자와 용량 재검사

Not Done

만들지 않은 기능은 이유와 함께 명세서에 적었습니다. 문자와 메일 발송은 외부 서비스 계약이, 지도는 API 키가, 관리자 통합 로그인은 학교 정보전산원 협의가 필요합니다.
