FOX AI 연구소 공식 사이트와 관리자 CMS

In-house2026.06 ~ 운영 중

Overview

연구소는 초등학생 대상 AI·코딩 프로그램을 운영합니다. 학부모가 프로그램과 수업 방식을 확인하고 상담을 신청할 공식 사이트가 필요했고, 2026년 6월에 만들기 시작해 본사 사이트들과 메뉴를 묶어 통합했습니다.

사이트를 연 뒤 공지와 사진이 자주 바뀌어, 직원이 직접 고칠 수 있게 화면과 내용을 나누고 관리자 CMS를 만들었습니다.

Architecture

내용을 고치는 길

관리자 CMS이름과 비밀번호 로그인→ 저장 대행Apps Script, GitHub 토큰 보관→ GitHubdata/*.json과 사진, 한 번의 커밋

내용을 보여 주는 길

GitHub Pages1~2분 안에 배포→ 본사 서버 페이지 (ai.foxconnect.kr)화면 틀만 두고, 열 때마다 최신 내용을 읽음

내용을 바꿀 때는 본사 업로드가 필요 없고, 화면 코드를 바꿀 때만 업로드를 요청합니다.

What I Did

  • 첫 화면 시안을 여러 개 만들어 비교한 뒤 하나로 정하고, 전체 페이지를 반응형으로 퍼블리싱
  • 글자 대비와 터치 영역을 웹 접근성 AA 기준에 맞춤
  • 관리자 CMS: 프로그램, 공지·소식, 팝업, 대회 사진, 설정 메뉴와 변경 이력
  • 상담 신청 폼: 접수 내용을 구글 시트에 쌓고 담당자에게 메일 알림 (Apps Script)
  • 운영 문서: 관리자 사용법, 처음 설정 방법, 본사 업로드 파일 만드는 법을 README로 정리

Problem Solving

콘텐츠를 고칠 때마다 필요하던 본사 서버 업로드

문제
자주 바뀌는 내용이 HTML에 섞여 있어, 공지 한 줄을 고쳐도 제가 코드를 고치고 본사에 서버 업로드를 요청해야 했습니다.
해결
내용을 JSON으로 빼서 GitHub Pages에 두고, 본사 서버의 페이지가 열릴 때 이 JSON을 읽어 화면을 채우게 했습니다. GitHub에서 내용을 못 받으면 HTML에 들어 있는 기본 내용이 보이게 해서 사이트가 깨지지 않습니다.
결과
2026년 10월 1일부터 6일까지 내용 수정 12건이 코드 수정과 본사 업로드 없이 반영됐습니다. (저장소의 CMS 커밋 기록 기준)

GitHub 계정이 없는 직원도 저장할 수 있어야 함

문제
GitHub에 저장하려면 토큰이 필요한데, 직원마다 계정과 토큰을 만들게 할 수는 없었습니다.
해결
토큰은 Apps Script 설정에 숨기고, CMS는 이름과 비밀번호로 Apps Script에 로그인해 저장을 대신 요청합니다. 비밀번호를 다섯 번 틀리면 10분 동안 잠기고, 비밀번호 로그인으로는 내용과 사진만 바꿀 수 있게 막았습니다.
결과
담당자가 바뀌면 비밀번호만 바꾸면 되고, 변경 이력에는 로그인할 때 적은 이름이 남습니다.

두 사람이 동시에 고치면 한쪽 수정이 사라질 수 있음

문제
CMS를 여러 사람이 쓰면, 먼저 저장된 내용을 나중에 저장한 사람이 모르고 덮어쓸 수 있었습니다.
해결
저장 직전에 GitHub의 최신 파일을 다시 읽고, 내가 불러온 뒤에 바뀌었으면 저장을 멈추고 새로고침을 안내합니다. 여러 파일과 사진은 Git 데이터 API로 한 번의 커밋에 묶어 반쯤 저장되는 경우를 없앴습니다.
결과
변경 이력에서 원하는 시점으로 되돌릴 수 있고, 저장 뒤에는 10초마다 배포된 내용을 비교해 반영 완료를 화면에 표시합니다.

모바일에서 첫 화면이 무거움

문제
원본 사진과 한글 글꼴 전체를 그대로 받아, 휴대폰에서도 PC용 큰 사진을 받았습니다.
해결
사진을 WebP로 바꾸고 480, 960, 1440px 세 크기로 나눴습니다. 화면 밖 사진은 나중에 불러오고, 글꼴은 한글 상용 2,350자만 남겨 직접 올렸습니다.
결과
페이지 용량 1,766KB에서 578KB, 모바일 이미지 전송량 87% 절감, 웹폰트 1,211KB에서 222KB. 배포 전 브라우저에서 직접 측정했습니다.

Decisions

  • 본사 서버를 관리할 사람이 없어 Node나 DB 서버를 둘 수 없었습니다. 도메인을 GitHub Pages로 돌리기, 본사 서버가 자동으로 받아 가기, 본사에 화면만 한 번 올리고 내용은 GitHub Pages에서 읽기 중 마지막을 골랐습니다. 본사 서버를 다시 건드리지 않고 내용을 바꿀 수 있고, Git 기록이 그대로 변경 이력이 됩니다.
  • 처음 넣었던 AI 생성 이미지를 실제 수업 사진으로 모두 바꿨습니다. 학부모가 보는 사이트라 실제 수업 모습을 보여 주고 싶었습니다.
  • 기준이 모호하던 맞춤 추천 기능을 실제 운영 중인 과정 데이터로 다시 짰습니다.
  • 누를 수 없는 카드에 붙어 있던 반응 효과를 뺐습니다. 눌리는 것처럼 보여 잘못 누르게 만들었기 때문입니다.
  • 제목 서체는 라이선스가 확인되지 않아 한 번 뺐다가, SIL OFL을 확인한 뒤 고지 파일과 함께 다시 넣었습니다.

Known Limits

  • 로그인 잠금은 사람별이 아니라 전체에 걸립니다. 비밀번호 하나를 함께 쓰는 구조이고, 이름은 직접 적는 값이며, Apps Script는 접속 IP를 알려 주지 않아 사람을 나눠 셀 기준이 없습니다. 그래서 누가 틀렸든 연달아 다섯 번 틀리면 모두 10분 동안 들어갈 수 없습니다.
  • 변경 이력에 남는 이름도 로그인할 때 직접 적는 값이라, 본인 확인을 거친 기록은 아닙니다.
  • 직원이 늘면 사람마다 계정을 두고, 잠금과 변경 이력을 계정 기준으로 바꾸는 것이 다음 단계입니다.
