어떤 개발자인가요?

요구사항을 듣는 일부터 개발, 운영, 그리고 운영 뒤 점검까지 한 서비스의 전 과정을 직접 해 본 개발자입니다.

시작은 게임 서버였습니다. 2018년부터 2년 가까이 동시 접속 50~80명 규모의 Minecraft 서버를 총관리자로 운영했습니다. 포트포워딩과 도메인 연결을 직접 했고, 플러그인이 말썽을 부리면 소스 코드를 열어 원인을 찾았습니다. 그때 컴퓨터를 전공하기로 정했습니다.

2025년 9월에 폭스커넥트 AI 연구소에 인턴으로 들어가 12월에 정규직이 됐습니다. 지금은 연구소 공식 사이트와 외부 대학 의뢰 사이트를 혼자 맡아 만들고 운영합니다. 혼자 맡다 보니 만들고 끝낼 수가 없었고, 그래서 납품한 것을 다시 점검하는 습관이 생겼습니다.

혼자 끝까지 만들어 본 서비스가 있나요?

연구소 공식 사이트와 관리자 CMS를 기획부터 운영까지 혼자 맡았고, 2026년 6월부터 운영하고 있습니다.

전에는

공지 한 줄을 고쳐도 직원이 요청하면 제가 코드를 고치고, 다시 본사에 서버 업로드를 요청해야 했습니다. 직원이 직접 고칠 방법은 없었습니다.

지금은

직원이 관리자 화면에서 저장하면 1~2분 안에 반영됩니다. 도입 첫 주(2026년 10월 1일~6일)에 수정 12건이 저를 거치지 않고 올라갔습니다.

서버 없이

본사 서버를 관리할 사람이 없어 DB 서버를 둘 수 없었습니다. 바뀌는 내용만 JSON으로 빼서 GitHub Pages에 두고, 토큰은 Apps Script 안에 숨겼습니다.

덮어쓰지 않게

여러 직원이 동시에 고쳐도 먼저 저장된 내용이 사라지지 않도록 저장 직전에 버전을 비교합니다. 비밀번호가 새도 사이트 코드는 바꿀 수 없습니다.

쓰는 사람 말대로

도입 뒤 직원 요청을 받아 변경 이력과 되돌리기를 넣었습니다. 하루짜리 팝업이 안 보인다는 문의에는 시작일 표시를 넣었습니다.

질문

만들기 전에 왜 필요한지 묻습니다

개발을 모르는 직원이 불편을 말하면, 무엇이 불편한지 다시 묻고 그 사람의 말로 정리합니다. CMS에서 직원이 원한 것은 관리자 화면이 아니라 업로드 요청을 안 하는 것이었습니다.

설계

기능명세로 구조부터 세웁니다

화면, 데이터, 입력값 검사, 권한을 먼저 적고 담당자와 합의합니다. 문자 발송처럼 계약이나 협의가 필요한 기능은 이유를 적고 뺐습니다.

구현

막히면 원인을 찾아 끝까지 돌아가게 합니다

코드를 쓸 때는 AI의 도움도 받습니다. 그래도 설계는 제가 하고, 결과는 직접 확인합니다.

운영

만든 뒤에도 책임집니다

부하 테스트, 브라우저 측정, 커밋 기록처럼 확인할 수 있는 근거로 결과를 말합니다. 이 페이지의 숫자는 모두 그렇게 나온 것입니다.

설명하는 일도 자신 있습니다. 연구소에서 개발과 함께 수업도 맡아, 같은 내용을 초등학생에게는 게임 속 활동으로, 대전교통공사 신입사원 40명에게는 바로 쓸 수 있는 업무 예시로 바꿔 설명했습니다. 직접 기획하고 주강사로 진행한 Minecraft Education 과정 「마을을 지켜라!」(12주 24차시)는 대전광역시교육청 2025 늘봄 공식 프로그램으로 채택됐습니다.

부족한 점은 무엇인가요?

큰 팀의 규칙 안에서 코드 리뷰를 받으며 일한 경험이 부족합니다.

작은 조직에서 기획부터 운영까지 혼자 맡았기 때문에, 서비스가 처음부터 끝까지 어떻게 굴러가는지는 알게 됐습니다. 대신 제 코드를 다른 개발자가 읽고 고쳐 준 일은 거의 없었습니다.

입사하면 팀의 코드와 배포 방식을 먼저 익히고, 리뷰를 통해 제 습관을 다듬겠습니다. 그 위에서 왜 필요한 기능인지 먼저 묻고, 만들기 전에 범위를 문서로 맞추고, 만든 뒤에는 측정해서 확인하는 방식으로 기여하겠습니다.
