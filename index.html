소개

2025년 7월, 개발자가 한 명도 없는 교육 회사의 연구소에 AI 연구원으로 들어갔습니다. 아이들 수업을 기획하고 운영하는 일이 본업이었지만, 연구소 사이트가 필요해지자 직접 만들었고 팀 업무표가 불편하다는 말이 나오자 웹앱으로 바꿨습니다.

그러다 보니 기획부터 디자인, 개발, 배포, 운영 문서까지 한 사람이 끝까지 맡는 방식이 몸에 익었습니다. 외부 대학이 의뢰한 강사 양성 사이트도 같은 방식으로 혼자 만들었습니다.

AI 도구를 많이 씁니다. 대신 무엇을 만들고 무엇을 하지 않을지는 제가 정하고, 그 이유를 기록으로 남깁니다. 아래 프로젝트마다 그 기록을 하나씩 붙였습니다.

대학 사업단이 강사 양성 과정을 알리고 신청을 받는 사이트입니다. 같은 사이트를 세 번 만들었습니다. 화면을 확인하는 프로토타입(Next.js), 다른 개발자에게 넘길 퍼블리싱 파일(HTML), 실제로 돌아가는 서버(Express와 SQLite)입니다.

  • 교육생과 관리자 로그인을 분리하고, 승인 전이거나 정지된 계정은 로그인을 막았습니다.
  • 게시판 4종과 과정, 신청자 관리에 파일 첨부와 신청자 엑셀 내려받기를 붙였습니다.
  • 정원을 넘는 신청, 접수 기간 밖의 신청, 신청 인원보다 작은 정원 수정을 서버에서 막았습니다.
  • 모집 상태를 DB에 저장하지 않고 날짜로 계산하게 바꿔 상태가 어긋나는 문제를 없앴습니다.

표를 JavaScript로 그리던 코드를 일반 HTML로 되돌렸습니다. 나중에 이 화면을 JSP로 옮길 사람이 구조를 바로 볼 수 있어야 했기 때문입니다.

  • 첫 화면 시안을 9가지 만들어 비교한 뒤 하나로 정했습니다.
  • 이미지를 WebP로 바꾸고 화면 크기별로 나눠, 모바일에서 받는 용량을 87% 줄였습니다.
  • 한글 글꼴을 필요한 글자만 남겨 직접 올렸고, 글자 대비와 터치 영역을 웹 접근성 AA 기준에 맞췄습니다.
  • 막연하던 맞춤 추천 기능을 실제 운영 중인 14개 과정 기준으로 다시 짰습니다.

처음 넣었던 AI 생성 이미지를 모두 실제 수업 사진으로 바꿨습니다. 학부모가 보는 사이트에서는 그럴듯한 그림보다 실제 모습이 믿음을 준다고 봤습니다.
