01

FOX AI 연구소 사이트

콘텐츠를 고칠 때마다 필요하던 본사 서버 업로드 없애기

전: 공지 한 줄을 고쳐도

직원 요청→ 제가 HTML 수정→ 본사에 업로드 요청→ 반영

후: 직원이 CMS에서 직접

관리자 CMS이름과 비밀번호 로그인→ 저장 대행Apps Script, 토큰 보관→ GitHubJSON과 사진을 한 번에 커밋→ 본사 서버 페이지열 때마다 최신 내용 읽기
문제
공지, 프로그램, 대회 사진처럼 자주 바뀌는 내용이 HTML에 섞여 있었습니다. 한 줄을 고쳐도 제가 코드를 고치고 본사에 서버 업로드를 요청해야 했고, 직원들은 GitHub 계정이 없어 직접 고칠 방법이 없었습니다.
해결
바뀌는 내용을 JSON으로 빼서 GitHub Pages에 두고, 본사 서버에는 화면 틀만 남겼습니다. 직원은 이름과 비밀번호로 CMS에 로그인하고, GitHub 토큰을 숨겨 둔 Apps Script가 저장을 대신합니다. 여러 파일은 한 번의 커밋으로 묶고, 저장 직전에 최신 파일과 비교해 다른 사람이 먼저 고친 내용은 덮어쓰지 않게 했습니다.
결과
CMS를 쓰기 시작한 2026년 10월 1일부터 6일까지 내용 수정 12건이 코드 수정과 본사 업로드 없이 반영됐습니다.반영 시간: GitHub Pages 1~2분, 본사 서버는 캐시 때문에 최대 10분. 건수는 저장소의 CMS 커밋 기록 기준

회색은 전, 초록은 후. 막대 길이는 1,766KB를 기준으로 맞췄습니다.

문제
원본 사진과 한글 글꼴 전체를 그대로 받고 있어서, 휴대폰에서도 PC용 큰 사진을 받았습니다. 외부 검토에서도 첫 화면이 무겁다는 의견이 나왔습니다.
해결
사진을 WebP로 바꾸고 480, 960, 1440px 세 크기로 만들어 화면에 맞는 것만 받게 했습니다. 화면 밖 사진은 나중에 불러오고, 글꼴은 한글 상용 2,350자만 남겨 직접 올렸습니다. 검토 의견은 항목별로 확인해 세 단계로 나눠 반영했습니다.
결과
페이지 용량 1,766KB에서 578KB, 모바일 이미지 전송량 87% 절감, 웹폰트 1,211KB에서 222KB.측정 조건: 배포 전 브라우저에서 직접 측정, 화면 크기 3구간(모바일, 태블릿, PC) 확인

03

우송대학교 강사 양성 누리집

모집 상태를 저장하지 않고 날짜로 계산하는 수강 신청 구조

원래 자료: 상태 값을 따로 들고 있음

과정 정보+ 상태 '접수중'사람이 바꿔야 함→ 기간이 지나도 '접수중'으로 남을 수 있음

바꾼 구조: 볼 때마다 계산, 신청은 서버가 다시 검사

오늘 날짜+ 신청 시작일, 종료일→ 상태 계산접수예정 / 접수중 / 모집종료
수강 신청→ 서버 검사접수중인지, 정원, 계정 승인·정지→ 저장 또는 거부
문제
받은 자료에는 과정마다 '접수중' 같은 상태 값이 따로 붙어 있었습니다. 이 값을 DB에 그대로 저장하면, 신청 기간이 지나도 누군가 바꾸기 전까지 '접수중'으로 남아 화면 표시와 실제 신청 가능 여부가 어긋날 수 있었습니다.
해결
상태를 입력 항목에서 빼고, 조회할 때마다 신청 시작일과 종료일을 오늘 날짜와 비교해 접수예정, 접수중, 모집종료로 계산했습니다. 수강 신청은 서버가 다시 검사해 접수중이 아니거나 정원이 찼거나 승인 전·정지 계정이면 거부하고, 신청 인원보다 작은 정원으로 고치는 것도 막았습니다.
결과
관리자가 상태를 손으로 바꿀 일이 없어졌고, 화면 표시와 신청 가능 여부가 같은 기준을 따릅니다.검증: 서버 기능 점검 38개 항목 모두 통과 (정원 초과 거부, 정지 계정 차단, 한글 첨부파일 왕복 포함)

SmartVision 시각장애인 보조 기기

라즈베리파이에서 돌지 않던 객체 인식을 줄여 실시간 음성 안내로

라즈베리파이 5 한 대에서 도는 흐름 (초록 테두리가 제 담당)

PiCamera2실시간 영상→ 객체 인식YOLOv8n, 위험 객체 12종→ 방향 계산화면을 셋으로 나눔→ 음성 안내gTTS, pygame
마이크→ 음성 명령큐알, 객체, 온도, 종료 등→ 모드 전환객체 모드 / QR 메뉴판 모드
문제
보드가 10주차에야 도착했습니다. 그전까지 데스크톱에서 만든 인식과 음성 기능이 라즈베리파이에서는 패키지 충돌과 성능 한계로 돌지 않았습니다.
해결
인식 모델을 가장 가벼운 YOLOv8n으로 바꾸고 패키지를 다시 구성했습니다. 안내 음성이 마이크로 다시 들어가 명령으로 잘못 인식되는 문제는 음성이 나오는 동안 듣기를 멈춰서 막았고, 같은 안내가 반복되지 않도록 3초 간격을 뒀습니다. 발열은 쿨러와 방열판으로 줄였습니다.
결과
Raspberry Pi 5에서 초당 5~10프레임으로 인식하고, 인식 후 1~2초 안에 음성으로 안내합니다. 졸업 작품 2위, 학점 A+.측정 조건: Raspberry Pi 5, PiCamera2, YOLOv8n. 캡스톤 최종보고서 기준
